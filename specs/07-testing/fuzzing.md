# Fuzzing

Replacing well-tested crates with hand-written parsers moves the risk into our own code, so every parser of untrusted input is fuzzed continuously.

| Target | Input source | Properties to check |
| --- | --- | --- |
| JSON reader | Untrusted processes on `agent.sock` | Strict profile enforced: valid UTF-8, no unpaired surrogates, no duplicate keys, integers within ±2^53, depth ≤ 32; non-conforming input rejected with `-32700`; no panics |
| Frame reader | Sockets | Frames over 1 MB rejected before allocation; partial and interleaved streams |
| JSON writer | Engine output | Everything emitted conforms to the strict profile (round-trip) |
| TOML subset parser | Policy and configuration files | No panics; rejects anything outside the subset |
| Bash parser | Agent command lines | No panics; unparseable input classified as dynamic; differential checks against bash |
| Bash lexer (`bash_lex`) | Agent command lines | No panics; deterministic; token spans tile the line, segments tile each word; here-document bodies follow a newline, belong to an earlier `<<` or `<<-`, and their segments tile the body; rejections point inside the input |
| Bash parser, simple and compound commands, functions, substitutions and here-documents (`bash_parse`) | Agent command lines | No panics; deterministic; fails whenever the lexer fails, with the same error (and may fail on an error inside a substitution body); rejections point inside the input; on success every word token outside an unsupported construct is exactly one assignment, command word, redirection target, `!`, reserved word, loop word, case subject or pattern, or function name of the tree, every such redirection token one redirection, every here-document body exactly one here-document, each part lies inside the command that holds it, compound lists are non-empty, simple commands of each script come in source order without overlapping, every function call names earlier definitions of the line, every substitution's script has the same structure in the text it indexes and marks no call, and only here-documents and here-strings are marked as feeding an interpreter |
| Sandbox denial log entries (`sandbox_log`) | The unified log; report text partly chosen by the denied process (its name, the path it asked for) | No panics; deterministic; an entry is attributed only within the 64 KiB size limit, with exactly a report line and a tag line, by a tag that is that last line and reads back to itself; process, operation and argument bounded and free of control characters; count at least 1 (KNSH-047) |
| TLS ClientHello reader (`tls_client_hello`) | Proxy connections | No panics; deterministic; waits for more bytes only below the 20 KiB read limit; an extracted name is a valid, normalised host name that matches itself and nothing else; a hello without a name or with Encrypted Client Hello never matches a named host; bytes after a complete hello do not change the result, and a hello that completes is never refused on a prefix; runs with `-malloc_limit_mb=1` (KNSH-061) |
| Secret redactor (`redactor`) | Command output (any bytes) and secret values | No panics; the output is the same however the stream is chunked; never more held back than the bound; outside the markers, no secret's exact value, base64 (standard or URL-safe, padded or not) or hex (either case), nor, once percent-decoded, the value itself (checked when no secret holds `%`) (KNSH-090) |
| Arithmetic expressions of the native interpreter (`arith_expr`) | Script text and variable values (agent-controlled) | No panics and no stack overflow (nesting bounded at bash's 1,024 levels); deterministic, variables included; every arithmetic error has bash's shape `expression: message (error token is "…")` (KNSH-097) |
| Word expansion of the native interpreter: brace expansion, `IFS` splitting, pathname expansion with every glob option, extended glob patterns (`word_expansion`) | Script text, variable values and file names (agent-controlled) | No panics and no stack overflow; deterministic, arguments included; a run ends only in a status, a refusal, a nesting or expansion limit, or a command-start failure; no argument holds NUL (KNSH-098) |
| `[[ … ]]`, `test` arguments, `printf` formats and `read` input of the native interpreter (`builtin_conditional`) | Script text and input (agent-controlled) | No panics and no stack overflow; deterministic, output and variables included; a run ends only in a status, a refusal, or a nesting or expansion limit (KNSH-102) |
| HTTP CONNECT and SOCKS handling | Proxy connections | No panics; malformed requests refused |

Test-only crates (fuzzers, property testing) are allowed under the [dependency policy](../04-non-functional-requirements/supply-chain.md).

## Harness

The targets live in `fuzz/`, a test-only workspace outside the shipped one (NFR-SUP-05); its crates are vendored like every other dependency. Each target's properties are a plain function in `fuzz/src/checks.rs` (JSON), `fuzz/src/toml_checks.rs` (TOML), `fuzz/src/bash_checks.rs` (bash lexer and parser), `fuzz/src/sandbox_log_checks.rs` (sandbox denial log entries), `fuzz/src/proxy_checks.rs` (proxy handshakes, target `proxy_handshake`), `fuzz/src/tls_checks.rs` (TLS ClientHello reader, target `tls_client_hello`) or `fuzz/src/redaction_checks.rs` (secret redactor, target `redactor`), which the stable test suite also runs over every seed and every saved crash (`fuzz/regressions/<target>/`), so a crash found once stays a failing test until it is fixed.

- **CI:** every push runs each target for 60 seconds (`scripts/fuzz.sh`) on a pinned nightly. A crash, a hang (over 10 seconds on one input) or a property failure fails the pipeline, and the crashing inputs are uploaded as an artefact.
- **Local:** `cargo +nightly fuzz run <target>` runs open-ended and grows the checked-in corpus; `scripts/fuzz.sh <seconds> <target>` runs time-boxed.
- **Allocation limit:** the frame reader target runs with `-malloc_limit_mb=2`: libFuzzer treats any single allocation of 2 MiB or more as a crash, which checks that no length prefix can make the reader allocate beyond the 1 MB payload limit (NFR-SEC-07).
- **Seeds:** the JSON reader starts from every strict-profile accept and reject sample; the frame reader from valid, interleaved, oversized, truncated and rule-breaking frame sequences; the TOML parser from the policy-profile and hook examples on their spec pages and accept and reject samples for each subset rule.
- **TOML round trip:** every document the TOML parser accepts is written out again by an independent writer in the fuzz crate (all tables inline) and must read back to an equal tree.
